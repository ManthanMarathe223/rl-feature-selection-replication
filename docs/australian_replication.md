# Australian Replication Experiment

## A. Objective

This is the first research experiment after the single-episode smoke test. It runs the existing feature-selection system on the Australian Credit Approval dataset only, across the four epsilon values inferred from Figure 2 and five project-selected seeds.

The paper reports Australian accuracy of `85.55 +/- 0.039%`. That value is a comparison target only and is never used to tune the experiment.

## B. Dataset

- Dataset: Australian Credit Approval
- Source file: `data/raw/australian/australian.dat`
- Input feature universe: all 14 inspected Australian features
- Target: the final binary class column
- WPBC and Sonar are not run in this experiment

## C. Reconstruction Assumptions

- `alpha=0.5` and `gamma=0.7` are reconstruction candidates from the independent FSRLearning implementation. They are not official paper parameters.
- Epsilon values `0.3, 0.4, 0.5, 0.6` are inferred from Figure 2.
- Initial subset size is fixed at `1` because the paper specifies random initial states but not their size distribution.
- Seeds `2021` through `2025` are project reproducibility choices, not paper settings.
- The episode runner uses `aor_contribution_mode="reward"` for this experiment. The paper's notation also permits a state-value-difference interpretation, so this choice is a documented reconstruction assumption.
- SVM evaluation uses the existing configurable sanity-check settings: RBF kernel, `C=1.0`, `gamma="scale"`, no scaling, stratified 80/20 holdout, accuracy scoring, and the run seed as the split seed. These settings are not claimed to come from the paper.
- Each run uses 100 episodes and allows enough steps to reach the all-features terminal state from a one-feature initial subset.

## D. Parameters

| Parameter | Values | Provenance |
|---|---|---|
| Epsilon | 0.3, 0.4, 0.5, 0.6 | Figure-inferred |
| Alpha | 0.5 | FSRLearning reconstruction candidate |
| Gamma | 0.7 | FSRLearning reconstruction candidate |
| Episodes | 100 | Project experiment design, consistent with the approximate Figure 2 horizon |

| AOR contribution | reward | Project reconstruction assumption |

## E. Experimental Design

The design contains 20 runs: four epsilon values multiplied by five seeds. Each run creates fresh environment, TD, AOR, and policy components, then executes 100 episodes. Within a run, state visits, TD values, and AOR history persist across episodes as required by the connected components.

Raw episode-level observations are written to `results/raw/australian_episode_results.csv`. Run summaries are written to `results/tables/australian_replication_results.csv`. The paper comparison is written to `results/tables/australian_paper_comparison.csv`.

## F. Results

Results are generated by:

```powershell
python -m experiments.baseline.run_australian_replication
```

The summary table records best observed accuracy, best state and episode, final accuracy, selected-feature counts, state-visit counts, transitions, average reward, maximum state value, runtime, and termination reason for every seed/epsilon run. Plot files are written under `results/figures/`.

## G. Comparison With Paper

`results/tables/australian_paper_comparison.csv` compares each epsilon's mean best accuracy with `0.8555` and standard deviation `0.00039`, the decimal equivalents of the reported `85.55 +/- 0.039%`.

The paper number is not used as an optimization target, stopping condition, or parameter-selection criterion.

## H. Deviations From Paper

The paper does not provide enough information to guarantee an exact numerical reproduction.

Known deviations or unresolved choices include the train/test protocol, SVM hyperparameters, scaling, random-state semantics, exact alpha/gamma values, initial-state distribution, and the relationship between reward and AOR contribution. The experiment preserves these as explicit project settings rather than presenting them as paper facts.

## I. Limitations

- This is one dataset and one first-pass reconstruction.
- The paper's reported accuracy cannot validate the implementation by itself.
- The current SVM evaluator's holdout protocol is a project assumption.
- Runtime measurements are machine-dependent.
- The experiment does not perform sensitivity analysis or compare alternative WPBC/Sonar interpretations.
- Results are generated from the current working tree; the recorded Git revision is included when available.

## J. Interpretation

Use the results to inspect trajectory behavior, reproducibility, epsilon effects, feature-subset sizes, and reward/value traces. Do not interpret agreement or disagreement with the paper's accuracy as proof of correctness until the unresolved experimental protocol is independently established.
